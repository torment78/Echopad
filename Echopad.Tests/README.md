# EchoPad regression checks

Run on Windows with the .NET 10 SDK:

```powershell
dotnet run --project Echopad.Tests -c Release
```

Runs 111 checks covering data migration, 15-second rolling capture and WAV export, waveform loading, copy gesture lifecycle, modifier chords, MIDI parsing/release thresholds, profile persistence/linking, settings merge behavior, route toggles, fixed pad brightness, PNG import/persistence/rendering, updates and installer downloads, and WPF page construction. It renders all settings and pad tabs, the main window and shortcut dialog into the test output directory's `previews` folder.

Migration fixtures cover old user/executable folders, relative media paths, recordings, both PNG states, named/active profiles, hotkeys and MIDI, trim/routing, Unicode, unknown JSON properties, source priority, external-path preservation, filename collisions, existing destination data, one-time completion and retries after malformed JSON or a blocked media copy. Sources remain intact; tests never migrate the real user's files or execute an installer.

Installer-download fixtures cover release asset selection, URL/size/hash validation, complete and partial transfers, progress, cancellation, oversized/truncated/corrupt payloads, HTTP errors and redirects. Injected save/launch/close callbacks verify that the app closes only after a successful verified handoff; save failures and canceled Windows prompts keep it open. These tests use generated bytes, not executable installers.

Tests use fake device lists and a unique data directory under the build output. They do not open audio devices, MIDI ports, or the user's settings. The waveform check uses an offscreen, non-activating WPF window to exercise the real Loaded/background-worker path. A VBAN packet test sends generated silence between two temporary UDP sockets on localhost. Update checks use controlled HTTP responses and do not require network access. Live audio and hardware controller checks still need a normal app run.

Most documentation screenshots are copied from the `previews` folder into `docs/images/current` after visual review. Keep `trim-section.png`: it is a supplied screenshot of the complete trim interface and should not be replaced with the synthetic waveform render. The update-available screenshot is explicitly labeled as an example. Test artwork is generated by the harness; the tests do not access user media.
